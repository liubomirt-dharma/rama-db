# Поисковые страницы и карточки ссылок видеотеки «Рама»

## Что получает посетитель

Главная страница сохраняет интерактивный каталог и прежние адреса с `#cat=`, `#source=` и параметрами поиска. В подвале есть обычные HTML-ссылки на каталог выпусков и тематический указатель. От них можно пройти ко всем индексируемым материалам с отключённым JavaScript. Заголовок выпуска в карточке видео открывает его постоянную страницу. Кнопки просмотра и избранного в интерактивном каталоге работают по-прежнему.

| Адрес относительно `/rama-db/` | Назначение |
|---|---|
| `videos/` | Все выпуски по дате публикации |
| `video/83AuwJ6a-Oo/` | Страница выпуска, плеер, темы, главы, описания и дополнительные источники |
| `video/83AuwJ6a-Oo/?t=436` | Этот же выпуск с началом воспроизведения на 00:07:16 |
| `topics/`, `sections/varna/` | Указатель и тематический раздел |
| `topics/science/`, `topics/brahmacharya/` | Категория или подтема с привязанными материалами и переходами к главам |
| `seminars/war-seminar/` | Семинар с перечнем относящихся к нему выпусков и материалов |

Для адресов используются постоянные ID. Правка названия сохраняет входящие ссылки. У материала без тайм-кода есть якорь по ID записи. На странице выпуска ссылка со значением `t` выбирает существующую главу и передаёт её секунду YouTube. С отключённым JavaScript в оглавлении остаются прямые ссылки на YouTube с соответствующими отметками.

Кнопка «Поделиться» есть у темы, раздела, семинара, видео и главы. В интерактивном каталоге она также доступна в окне просмотра и над результатами выбранной темы. Меню поддерживает копирование, Facebook, Telegram, WhatsApp и системную отправку на совместимых устройствах. Ссылка на главу сохраняет время. Её социальная карточка относится ко всему выпуску, а Telegram, WhatsApp и системное меню также получают название фрагмента. Избранное и персональные комбинации фильтров остаются в браузере пользователя.

## Как устроена сборка

Единственный источник содержимого — публичный массив `window.RAMA_DB` в `assets/catalog.js`. Архивная навигация находится в `assets/shelling-navigation.js`, интерфейс поиска — в `assets/catalog-ui.js`. Страница каталога загружает эти файлы с `defer`. На статических страницах выпуска и темы посетитель получает только нужный HTML, небольшие стили и сценарии для передачи ссылки и выбора главы.

Генератор на Python создаёт HTML, canonical, Open Graph, Twitter Cards, JSON-LD, обычные ссылки, `sitemap.xml`, `robots.txt` и `404.html`. Метаданные главной обновляются между комментариями `seo:head`. Для новых разделов и категорий используются их записи в справочнике. Сегмент `seminar` в ID через дефис выделяет маршрут семинара. В карту входят активные непустые подборки. Повторяющиеся названия выпусков различаются номером в метаданных. Служебные тайм-коды доступны в оглавлении собственного выпуска.

Из корня репозитория выполните:

```sh
python scripts/build_seo.py
python -m http.server 8767 --bind 127.0.0.1 --directory _site
```

Это создаёт готовую к публикации папку `_site/`. Для предпросмотра откройте `http://127.0.0.1:8767/`. Основные страницы используют относительные внутренние ссылки. Canonical, sitemap и социальные метаданные всегда указывают на публичный HTTPS-адрес. Страница ошибки содержит ссылки от корня проекта, чтобы открываться и при ошибке в глубоко вложенном адресе.

Для проверки сборки существует также команда `RAMA_SEO_ROOT=_site python -m unittest discover -s tests -p test_seo_static.py -v`. Полная регрессия, включая настоящее браузерное открытие ссылок, запускается из репозитория командой `python -m unittest discover -s tests -v`.

### Публикация на GitHub Pages

1. Для автоматического построения и публикации следующих обновлений выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Вкладка **Actions** должна быть доступна в репозитории.
2. После слияния в `main` процесс **Build and publish the video library** читает публичную базу, проверяет обложки, строит страницы, тестирует артефакт и передаёт его GitHub Pages. После переключения режима у уже существующего коммита процесс можно запустить через **Actions → Run workflow**.
3. Дождитесь успешного шага **Deploy**. Откройте главную, одну страницу видео, ссылку с временем, семинар, карту сайта и заведомо отсутствующий адрес под `/rama-db/`. Для отсутствующего адреса проверьте HTTP 404.
4. При публикации из ветки GitHub Pages использует включённый в репозиторий готовый снимок. Для последующих правок в этом режиме сначала выполните `python scripts/build_seo.py --out .`, затем включите изменившиеся и удалённые сгенерированные файлы в тот же коммит, что и данные. Workflow пропускает собственный деплой, пока выбран источник «ветка».

При смене домена обновите `BASE` в генераторе, адреса в документации и ожидания канонического домена в тестах. Затем выполните полную сборку.

## Как обновить социальное превью

Основная карточка — `assets/social-cover.jpg`, JPEG 1200 × 630. Использованы оригинальная иллюстрация проекта, название центра и крупная надпись «Библиотека видео». Она подходит для главной, указателей и тематических подборок. Для изменения фирменной графики замените файл, сохранив размеры, либо обновите свойства `COVER` в генераторе.

Для видео сборка GitHub Actions пытается получить JPEG самого выпуска от YouTube. Она проверяет формат и размер 480 × 360, затем сохраняет локальную копию в `assets/video-covers/` внутри публикуемого артефакта. Небольшая подстановочная картинка YouTube отбрасывается. Семинар использует доступную обложку входящего в него выпуска. При отсутствии обложки выбирается фирменная карточка. Просмотр страницы пользователем не запускает загрузку обложек всего каталога.

Для той же проверки при локальной сборке установите Pillow и запустите `python scripts/build_seo.py --fetch-thumbnails`. Обычная сборка и регрессия исходных HTML обходятся стандартной библиотекой Python. Чтобы ускорить обновление изображения в кэшах внешних платформ после ребрендинга, можно дать ему новое имя и обновить `COVER`.

## Google Search Console

1. Войдите в Search Console под аккаунтом владельца. Добавьте ресурс типа **URL с префиксом** и укажите точный адрес `https://liubomirt-dharma.github.io/rama-db/`. [Google Search Console](https://search.google.com/search-console/)
2. Выберите подтверждение через HTML-файл. Сохраните выданный Google файл `google….html` в корень репозитория без изменения имени и содержимого. Сборка копирует его в корень сайта проекта. Альтернатива — настоящий тег `google-site-verification` в `<head>` главной **вне** блока `seo:head`. [Подтверждение права собственности](https://support.google.com/webmasters/answer/9008080)
3. После публикации проверьте, что выданный сервисом URL возвращает HTTP 200 и нужное содержимое. Нажмите **Подтвердить**. Оставьте файл или тег для повторных проверок.
4. В разделе **Файлы Sitemap** отправьте `https://liubomirt-dharma.github.io/rama-db/sitemap.xml`. Проверьте статус обработки и число обнаруженных адресов. [Отправка sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
5. Для важного выпуска вставьте его постоянный адрес в **Проверку URL**, выполните проверку опубликованной страницы и нажмите **Запросить индексирование**. Для тайм-кодов отправляйте основную страницу выпуска. В отчётах **Индексирование страниц** и **Индексирование видео** изучайте ошибки загрузки, выбранный canonical, доступность плеера и миниатюр. [Проверка URL](https://support.google.com/webmasters/answer/9012289)
6. В отчёте **Эффективность** включите клики, показы, CTR и среднюю позицию. Режимы «Запросы» и «Страницы», фильтры по стране и устройству и сравнение периодов покажут, по каким темам находят библиотеку. [Отчёт об эффективности](https://support.google.com/webmasters/answer/7576553)

## Bing Webmaster Tools

1. Войдите в Bing Webmaster Tools. Импортируйте подтверждённый ресурс из Google Search Console или вручную добавьте URL проекта. [Bing Webmaster Tools](https://www.bing.com/webmasters/)
2. При ручном подтверждении используйте настоящий файл `BingSiteAuth.xml` в корне репозитория или тег `msvalidate.01` в `<head>` вне генерируемого блока. После публикации откройте файл или проверьте исходный HTML, затем подтвердите сайт.
3. В **Sitemaps** отправьте полный адрес карты. Для диагностики выпусков используйте **URL Inspection**, для выборочной отправки новых страниц — **URL Submission**. Поисковые запросы, показы и клики доступны в **Search Performance**.

## Как проверить разметку и обновить превью после публикации

- В Rich Results Test проверьте публичный адрес **отдельного выпуска**. Посмотрите VideoObject, дату публикации, доступность thumbnailUrl и границы Clip. Schema Markup Validator дополнительно покажет WebSite, Organization, хлебные крошки и списки. [Google Rich Results Test](https://search.google.com/test/rich-results) · [Schema Markup Validator](https://validator.schema.org/)
- В Facebook Sharing Debugger вставьте канонический адрес, проверьте название, описание, изображение и нажмите **Scrape Again** после обновления. Для Telegram и WhatsApp отправьте ту же ссылку и ссылку с временем в собственный тестовый чат. Эти платформы независимо кэшируют карточки. [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/)
- Через PageSpeed Insights проверьте главную и страницу видео. Полевые LCP, INP и CLS появятся при достаточном объёме реальных посещений. Лабораторные сравнения этой версии приведены в отчёте. [PageSpeed Insights](https://pagespeed.web.dev/) · [Отчёт выпуска](docs/SEO_RELEASE.md)

## Ограничения индексирования

Файл проекта размещён по адресу `/rama-db/robots.txt`. Поисковые роботы запрашивают `/robots.txt` в корне **хоста**. Управление этим адресом относится к сайту `liubomirt-dharma.github.io`. При доступе к нему добавьте директиву `Sitemap: https://liubomirt-dharma.github.io/rama-db/sitemap.xml`, сохранив существующие правила. Для самого проекта работают метатеги robots, canonical, внутренняя перелинковка и отправка карты в обе поисковые панели.

На страницах выпусков плеер находится перед списком глав, его адрес доступен в исходном HTML, загрузка использует нативный `loading="lazy"`. VideoObject использует название, дату из каталога, адрес встраивания и миниатюру. Время суток, часовой пояс, продолжительность и URL исходного медиафайла в базе отсутствуют. При наличии только календарной даты публикуется известная дата; выпуск без даты сохраняет страницу, но исключается из разметки VideoObject. Для Clip используются содержательное название, начало и следующая отметка оглавления как граница главы. Последняя глава без известного окончания остаётся доступной по времени. Служебные главы не выдвигаются как ключевые моменты. [Видео в Google Поиске](https://developers.google.com/search/docs/appearance/video) · [Требования к VideoObject и Clip](https://developers.google.com/search/docs/appearance/structured-data/video)

Решение о включении страниц в индекс, расширенных результатах и показе ключевых моментов принимают поисковые системы. После публикации сверьте разметку с действующими требованиями Google и фактическими отчётами Search Console. При появлении проверенных данных о длительности или времени публикации их можно передавать из того же каталога.
